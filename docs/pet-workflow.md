# 做一套新桌宠 · 标准工作流

> **改已有形象的素材 / 加动作** → 看 [`素材制作工作流.md`](./素材制作工作流.md)。
> **拿到一张新图不知道怎么拆** → 看 [`素材采集方法论.md`](./素材采集方法论.md)。
> 本文讲的是**从零做一套新形象**：要准备什么、怎么接线、怎么验收。

> **这份文档是流程，不是规格。规格在 [`pet-spec.json`](../pet-spec.json) 里，由工具导出。**
>
> 为什么这么分：手写的规格**一定会和代码漂移**。这个项目已经吃过好几次亏 ——
> 菜单漏了 `pat`/`patAngry` 的中文映射、README 写"待机链四个节点"实际是六个、
> 演示页的分组漏了 `eat`/`stretch`。所以**规格从运行时代码里读**，不手抄。

## 0. 一句话流程

```
① 建骨架   npm run new:pet -- <style-id> "显示名"
② 备素材   按 pet-spec.json 的 frames 清单准备 26 张图（AI 生成或手画）
③ 放素材   放进 assets/<style-id>/，源图留在 pet-art/character/
④ 校验     npm run verify:pet -- <style-id>
⑤ 接线     改 3 个常量：ACTIVE_STYLE / FRAME_FILES / manifest
⑥ 验收     npm run test + npm run preview
```

**做完之后在右键菜单「宠物形象」里就能切** —— 多套素材是自动列出来的

### 菜单里的先后：`manifest.json` 的 `order`

```json
{ "name": "我的宠物", "order": 5, "...": "..." }
```

数字小的排前面。**不写就排到最后**（所以新素材不写也能用）。

⚠️ **别指望目录名**。以前直接返回 `readdirSync` 的顺序 —— 在 APFS 上碰巧是
字母序，看起来"能用"，但那是巧合：换个文件系统就不一样了，而且**想让某套
排第一，光靠目录名根本做不到**。现在顺序由每套自己声明。

**每套的 `order` 不能重复** —— 重了的话顺序取决于目录扫描顺序，会飘。
`test-mainmenu.mjs` 的【1.988】守这条。
（`styleMenuItems()` 扫 `assets/` 下所有带 `manifest.json` 的目录）。

## 1. 一套宠物需要什么

### 1.1 素材规格

| 项 | 值 | 说明 |
|---|---|---|
| **尺寸** | **512 × 512** | 正方形，透明背景 |
| **格式** | `.webp` | 源图（PNG）留在 `pet-art/character/` |
| **构图** | 内容居中，**占高约 85%** | `tools/gen-frames.py` 会自动归一化 |
| **背景** | AI 生成时用**纯绿幕 `#00FF00`** | 之后抠掉（见下） |
| **命名** | 文件名 = `FRAME_FILES` 里的值 | 逻辑名**可以**和文件名不一样（`ready2` → `ready.webp`）|

### 1.2 图稿清单 —— **26 张**

> ⚠️ **这是硬要求。** 少一张，对应的动画就播不出来（`showFrame` 会打错误日志）。
> 完整清单见 `pet-spec.json` 的 `frames` 字段，`npm run verify:pet` 会逐张检查。

| 分类 | 张数 | 逻辑名 |
|---|---:|---|
| **常态 / 眨眼** | 4 | `awake` `blink` `slowBlink` `blinkTwice` |
| **待机彩蛋** | 2 | `eat` `stretch` |
| **睡觉三阶段** | 3 | `drowsy` `sleep` `startle` |
| **挥手** | 2 | `wave1` `wave2` |
| **被摸头** | 1 | `patHappy` |
| **生气** | 2 | `angry` `angryBlock` |
| **工作中** | 7 | `work0`…`work6` |
| **需要确认** | 1 | `needInput` |
| **出错** | 1 | `blocked` |
| **完成庆祝** | 5 | `ready0`…`ready4` |

### 1.3 「怎么动」的三种做法

| 做法 | 需要 | 成本 | 用在哪 |
|---|---|---|---|
| **换图**（多帧不同图稿）| **美术资源** | 高 | `working` `wave` `ready` `angry` `blinkTwice` |
| **位移**（同图 + `offsetX/Y`）| **零素材** | 低 | `sleep` 呼吸 · `startle` 惊醒 · `ready` 跳跃 |
| **静止**（单帧）| 零 | 零 | `needInput` `blocked` `drowsy` `patHappy` |

> ⚠️ **不要写"多帧但全是同一张图、又没有位移"** —— 那是**假动画**，
> 代码上看像有动画，实际完全是定格的。
> `selfTestFakeMotion()` 会在启动日志里报出来。
> **要定格就写 1 帧。**

## 2. 状态机 —— **10 个状态**

> 状态由 **DSH 插件**驱动（`pet-plugin/index.js`），不是随便加的。
> 加新状态要改三处：插件、`pet.js` 的触发点、`state-labels.js` 的中文名。

### 2.1 三个来源

| 来源 | 状态 | 谁触发 |
|---|---|---|
| **插件推** | `idle` `working` `needsInput` `ready` `blocked` | DSH 的会话事件 |
| **状态机自己** | `sleep` | 连续 50 秒空闲没人理 |
| **时刻**（`reportMoment`）| `wave` `startle` `pat` `patAngry` | 用户操作 |

### 2.2 对照表

| 状态 | 中文 | 触发 | 动画 | 气泡 |
|---|---|---|---|---|
| `idle` | 空闲 | DSH 空闲 | 待机链 6 节点按权重抽 | 定时 5s |
| `working` | 工作中 | DSH 在跑 | `working` 12 帧换图 | 定时 5s |
| `needsInput` 🔒 | 需要确认 | **有挂起的审批/提问** | `needInput` 单帧 | **常驻** + 30s/2m/5m/10m 催 |
| `ready` | 任务完成 | 从 working 落到 idle | `ready` 20 帧跳 5 次 | 定时 5.8s |
| `blocked` 🔒 | 出错 | 会话出错 | `blocked` 单帧 | **常驻** + 30s/2m/5m/10m 催 |
| `sleep` | 睡着 | 空闲 50 秒 | `sleep` 4 帧呼吸 | 定时 5s + 每 40s 一句 |
| `wave` | 打招呼 | 双击她 | `wave` 7 帧换图 | 定时 5s（20s 冷却）|
| `startle` | 被吵醒 | 睡着时被碰 | `startle` 3 帧弹起 | 定时 5s（20s 冷却）|
| `pat` | 被摸头 | 摸头累计够 | `patHappy` 单帧 | 定时 5s（5s 冷却）|
| `patAngry` | 被惹毛 | 摸太快 | `angry` 2 帧 | 定时 5s（无冷却）|

🔒 = `[fixed]`，**不可在菜单里关掉**（需求 4）

### 2.3 空闲内部的三个阶段

`sleep` 是**独立状态**，但它由 `idle` 内部的时间轴推进：

```
空闲 0s ──── 40s ──── 50s ──────── 被碰 ────────→ 回 idle
          drowsy    sleep        startle
          (困倦)    (睡着)        (惊醒)
```

## 3. 台词

### 3.1 文件位置（两层）

```
内置   <App>/dialogues/zh.md                              ← 跟着版本走
你的   ~/Library/Application Support/胖头鱼/dialogues/zh.md  ← 你改的
```

**新建一套宠物时，把 `dialogues/zh.md` 整个复制一份改词** ——
结构（哪些状态、几档催促）照抄，只换台词内容。

### 3.2 结构

```markdown
## working  ← 工作中 —— DSH 正在跑

- #1 正在努力中……
- #2 让我看看这个……

### 循环 10s
- #1 还在写……
- #2 快好了快好了
```

| 写法 | 含义 |
|---|---|
| `## 状态名 [fixed] ← 中文说明` | 状态。`[fixed]` = 不可关闭 |
| `- #N 台词` | 台词。**序号只给人看，不决定播放顺序**（永远随机抽）|
| `### 升级 30s` | **一次性**：到点说一次，之后不再说 |
| `### 循环 首次 [间隔]` | **反复**：首次等「首次」，之后按「间隔」说 |

⚠️ **「首次」别写太大** —— `working` 这种状态往往几十秒就结束，
首次写 45s 的话**永远不会触发**（实测踩过）。

### 3.3 各状态的台词规模（照这个量级写）

| 状态 | 句数 | 档 |
|---|---:|---|
| `idle` | 10 | 升级 40s / 52s / 120s |
| `working` | 8 | 循环 10s |
| `needsInput` 🔒 | 11 | 升级 30s / 2m / 5m / 10m |
| `blocked` 🔒 | 11 | 升级 30s / 2m / 5m / 10m |
| `sleep` | 8 | 循环 40s |
| `ready` `wave` `pat` | 3~4 | 无 |
| `startle` `patAngry` | 3 | 无 |

### 3.4 催促档的语气走向（`needsInput` / `blocked` 专用）

```
刚进入 → 先报情况          「这里需要你确认一下！」
30 秒  → 提醒你来看        「看这里看这里！」
2 分钟 → 开始催            「喂——你还在吗？」
5 分钟 → 有点委屈          「我举着手好累的」
10 分钟→ 放弃 / 自嘲        「……（默默放下手）」
```

## 4. 工具链

| 命令 | 干什么 |
|---|---|
| `npm run new:pet -- <id> "名字"` | **建骨架**：目录 + manifest + 话术模板 |
| `npm run dump:spec` | 从运行时代码导出规格 → `pet-spec.json` |
| `npm run verify:pet -- <id>` | **校验一套素材**（缺哪张、尺寸对不对、命名对不对）|
| `python3 tools/gen-frames.py --action <名> --count N` | AI 生成候选帧（火山方舟 Seedream）|
| `python3 tools/add-frame.py` | 把选中的帧登记进 manifest |
| `npm run build:cutout` | 编译抠图工具（macOS Vision）|
| `npm run build:demo` | 打包单文件演示页到桌面 |
| `npm run preview` | 开发用动画预览 |
| `npm test` | 八个测试套件 |

### AI 生成的关键经验

| 坑 | 做法 |
|---|---|
| **输出是纯色背景但不透明** | 必须抠图（`tools/cutout`，macOS Vision）|
| **模型会画上你没要求的东西** | 提示词里写"**只画角色本人，不要画手**" |
| **模型会丢掉你没点名保留的元素** | 必须显式写"**务必保留 XX**"（实测丢过玩偶、丢过问号）|
| **姿势漂移** | 用现有帧当参考图 + `reference_strength` |
| **不要画符号**（问号、怒气符号）| 抠图后会留下、且批次间位置对不齐 |
| **一组图风格不统一** | 风格锁写进提示词，**分批生成后逐张比** |

## 5. 验收清单

做完一套新材料，逐条打勾：

- [ ] `npm run verify:pet -- <id>` 全绿（26 张、512×512、透明）
- [ ] `assets/<id>/manifest.json` 写好了 `name` / `description` / `frames`
- [ ] `pet-art/character/` 留着源图（**别删**，以后要重新裁）
- [ ] 话术文件有 **10 个状态**，每个都有中文说明
- [ ] `npm test` 八个套件全过
- [ ] `npm run preview` 里每个片段都能播、没有「静止」的意外项
- [ ] **右键 → 宠物形象** 里能切到新那套
- [ ] 启动日志里**没有** `假动画自检: ❌`
- [ ] 启动日志里**没有** `未知状态` / `资源加载失败`

## 6. 为什么规格要工具导出

这个项目里**"文档和代码不一致"至少踩了五次**：

| 踩到的 | 怎么发现的 |
|---|---|
| 菜单里显示 `pat` / `patAngry` 英文 | 用户看到 |
| README 写"待机链四个节点"，实际六个 | 检查时发现 |
| 演示页分组漏了 `eat`/`stretch`/`angry` | 用户问"哪些有动作" |
| 日志和预览页显示英文状态名 | 用户提"单看英文不直观" |
| `drowsy`/`patHappy` 是假动画 | 演示页标出「静止」 |

**共同点：手写的东西会漂移。**

所以：**规格从代码导出（`npm run dump:spec`），文档只写流程。**
改了 `pet.js` 就重新 dump 一次，规格永远是真的。
