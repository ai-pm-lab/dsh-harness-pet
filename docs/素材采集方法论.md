# 素材采集方法论 · 部件化拼装

> 你给图，我拆件；件不够，我列清单向你要。
> 这份文档回答一个问题：**怎么从零散给的图里，攒出一套能动的桌宠素材。**

---

## 一、核心思想：把宠物当成「部件的组合」

不要问"我需要哪些帧"，要问"**我需要哪些部件，以及它们怎么摆**"。

```
一帧画面  =  身体  +  手臂 ×2  +  眼睛 ×2  +  嘴巴  +  [道具]  +  [位移/缩放]
             ↑固定   ↑可换      ↑可换      ↑可换    ↑可加
```

**为什么这个视角有用**：

| 传统做法 | 部件化做法 |
|---|---|
| 每个动作都要一张完整的图 | 复用同一个身体，只换手臂/眼睛 |
| 缺一个动作 → 要重画一整张 | 缺一个动作 → 只要**一个部件** |
| 40 个动作 = 40 张图 | 40 个动作 = 3 个身体 × 5 种手臂 × 4 种眼睛… |

**这次的实际收益**：
- 双击的"揉脸"动作 = **一个 GIF**（28 帧）→ 直接就是一套手臂动作
- 工作中的打字 = **无手臂底图 + 单独手臂图** → 拼出 3 帧摆动
- 伸懒腰的眯眼 = **029 的身体 + 一条横杠**（眼睛部件的替换）

## 二、部件分类

### 2.1 身体（躯干 + 头，不可拆）

| | |
|---|---|
| **来源** | 每个"姿势"一张图 |
| **识别** | 去掉四肢/道具之后剩下的那坨 |
| **数量** | 有多少姿势就有多少个 |
| **月薪喵现有** | 57 张原图里，每个姿势一个 |

**关键**：身体通常是**最贵**的部件（要重画）✅ —— 所以能复用就复用 ✅

### 2.2 可换部件（真正省钱的地方）

| 部件 | 怎么识别 | 换它能得到什么 |
|---|---|---|
| **手臂 / 前爪** | 深色轮廓围出来的一小块，**通常在白色肚子或纯色底上** | 挥手、打字、揉脸、伸懒腰、摸头… |
| **眼睛** | **彩色**（这套是深蓝 `#2755a4`），竖圆角矩形 | 睁眼 / 眨眼 / 眯眼 / 闭眼 / 生气 / 困倦 |
| **嘴巴** | 深色小块，**夹在两只眼睛中间** | 微笑 / 平嘴 / 张嘴 / 问号 |
| **尾巴** | 身体一侧、带条纹 | 摇尾巴 |
| **耳朵 / 头发** | 身体顶部两侧 | 抖动 |

### 2.3 道具（外挂）

| | |
|---|---|
| **例子** | 笔记本、小鱼干、枕头、月亮 |
| **来源** | 你给的草图 + 我按画风重画，或你给成品图 |
| **关键** | 要么**完全在你给的图里**（直接裁），要么**我按你的草图重画** |

### 2.4 变换（不是部件，但同样省事）

| 变换 | 效果 | 这次用在哪 |
|---|---|---|
| **位移** `offsetX/Y` | 上下跳、呼吸、打字的小节奏 | 睡着（-3px 呼吸）、完成庆祝（原来有 -22px 跳跃）|
| **左右翻转** | 镜像姿势 | （还没用，但可以）|
| **缩放** | 弹一下 | 摸头的 `nudge` |

## 三、从一张图里提取部件的六种手法

> 按**可靠性从高到低**排。能用上面的就别用下面的。

### ⭐⭐⭐ 手法 1：做差（最准，优先用这个）

**要两张图**：含部件的 + 不含部件的（其余完全一样）。

```python
d = np.abs(np.array(with_part) - np.array(without_part)).max(axis=2)
ys, xs = np.where(d > 20)          # 差异区域 = 部件的位置和大小
```

**为什么最准**：不靠颜色阈值、不靠形状猜测，**像素级精确** ✅

**这次的应用**：
- 用户给了「无手臂底图」+「有手臂的成品图」→ 做差得到手臂 bbox **144×109**，
  和用户单独给的手臂图尺寸**完全一致** → 证明两张图严格对齐 ✅
- 两版底图做差 → 差异只有 **328 像素**，落在键盘那几道线上 → 一眼知道改了什么 ✅

**要跟用户要什么**：「**能不能把去掉手臂的那张也给我**」—— 这一句话省掉我半小时抠图。

### ⭐⭐⭐ 手法 2：直接要单独的部件图

用户手里往往就有 ✅ —— 直接要：
> 「**手臂单独给我一张 PNG 就行**（透明底）」

**这次**：用户给了「无手臂底图」+「单独手臂图」→ **零瑕疵**（不用抠、不用补）✅

### ⭐⭐ 手法 3：固定裁框 + 并集（做动作用）

**要一组帧**（GIF / 视频 / PNG 序列）。

```python
stack = np.array([np.array(f) for f in frames])
u = (stack[:,:,:,3] > 40).any(axis=0)      # 所有帧的并集
uy, ux = np.where(u)
box = (ux.min(), uy.min(), ux.max()+1, uy.max()+1)
```

⚠️ **绝对不要逐帧按各自的内容包围盒裁剪再对齐** ——
那样会把「**她在动**」这件事本身抹掉，动作就废了 ✅

### ⭐⭐ 手法 4：颜色阈值（找彩色部件）

**适合**：眼睛这种**颜色独特**的部件 ✅

```python
# 深蓝的眼睛：蓝明显大于红
blue = (a[:,:,2] - a[:,:,0] > 40) & (a[:,:,2] > 90) & (a[:,:,0] < 130)
```

**然后分左右**：按 x 的中点一分为二 ✅

**这次**：量到左眼 `x 164..182, y 148..217`、右眼 `x 264..285, y 140..214`、
颜色 `#2755a4` ✅

### ⭐ 手法 5：形状/位置约束（找深色部件）

**适合**：嘴巴、轮廓 ✅ —— 但要**用相对位置约束**，不能用"眼睛下方的深色"这种模糊条件 ✅

```python
# 嘴巴：夹在两只眼睛中间
mid = (bx.min() + bx.max()) // 2
left_max  = bx[bx <= mid].max()        # 左眼右缘
right_min = bx[bx >  mid].min()        # 右眼左缘
mouth = dark[eye_top:eye_bot+1, left_max+1:right_min]
```

⚠️ **踩过的坑**：一开始用"眼睛**下方**的深色像素"找嘴巴 ——
把**两条举起来的胳膊**也算进去了（029 是双手举起的姿势）✅

### ⭐ 手法 6：横移复制 / 逐行取色（补原位）

**只在前五种都不行时用** ✅ —— 因为"取一个颜色补整块"几乎一定会留痕 ✅

**这次试过 6 种全失败**，最后靠**重建分界线**才干净：

| 试过的 | 结果 |
|---|---|
| 四周一圈的中位色 | ❌ 圈里混进头发 → 米棕竖条 |
| 紧贴左右两列的中位色 | ❌ 眼睛上下跨底色 |
| 两眼之间的脸白（中位数）| ❌ 扫到胡子被拉灰 |
| 两眼之间的脸白（最亮）| ❌ 比脸更白 → 两块亮斑 |
| 横移复制（行对齐）| ❌ 两眼之间下半段就是胡子 |
| 逐列垂直插值 | ❌ 分界线是斜的 → 灰色渐变 |

**✅ 最终解法：重建那条分界线**
```
① 先在部件左右两侧（没被挡住的地方）逐列量出分界线高度
② 横向插值，把分界线穿过部件
③ 部件像素按分界线重涂：线以上用 A 色、线以下用 B 色
```

**根本原因**：那只眼睛**骑在「脸/头发」的分界线上** ——
左缘贴头发、右缘在脸上，**一个颜色永远不可能对** ✅

## 四、视角分析

用户给草图/参考图时，**先把视角读出来**再动手 ✅ —— 读错方向等于白做 ✅

### 4.1 看什么

| 线索 | 说明 |
|---|---|
| **能看到 Logo / 背面** | 视角在物体的**后面** |
| **能看到屏幕内容** | 视角在物体的**前面**（使用者那一侧）|
| **远边比近边窄** | 近大远小 → **近边在画面下方** |
| **某侧的侧面露出来了** | 灭点在那侧 → 物体朝那侧倾斜 |
| **哪条边最长** | 最长的那条边离观察者最近 |

### 4.2 这次的实例（笔记本草图）

| 观察 | 结论 |
|---|---|
| **能看到苹果 Logo** | 看到的是**屏幕盖的背面** → 视角在笔记本**后面** |
| **键盘面在右侧露出、往右后方收** | 灭点在**右后** → 笔记本向右后方倾 |
| **盖子下沿比上沿宽** | 近大远小 → 下沿离我们近 |
| **键盘面只露几条横线** | 被盖子挡掉大半 |

→ **第一版我画成"屏幕朝我们 + 几行代码"，方向完全反了** ✅

### 4.3 桌宠特有的视角约束

```
猫坐在笔记本后面看屏幕  →  我们在猫身后  →  看到的是笔记本的背面
```

**推导链**：宠物的朝向（面向我们）→ 道具和她的相对位置（在她身前）→
我们看到的是道具的哪一面 ✅

## 五、从状态倒推需要什么（缺口分析）

### 5.1 十个状态各需要什么

| 状态 | 需要 | 月薪喵现状 |
|---|---|---|
| **idle** 空闲 | 身体 ×1 + 轻微动（眨眼/呼吸）| ✅ |
| **working** 工作中 | 身体 + **手臂** + **道具** | ✅ 打字 + 眨眼 |
| **needsInput** 🔒 | 身体 + 表情（举手/问号）| ✅ |
| **ready** 完成 | **一段庆祝动作** | ✅ 040→044 × 5 趟 |
| **blocked** 🔒 | 身体 + 出错表情 | ✅ |
| **sleep** 睡着 | 困倦的身体 + **呼吸位移** | ✅ |
| **wave** 挥手 | **手臂** ×3 | ✅ |
| **startle** 被吵醒 | **一组惊醒帧** | ✅ 6 帧 |
| **pat** 摸头 | 眯眼表情 | ✅ |
| **patAngry** 摸烦了 | 生气表情 | ✅ |

### 5.2 缺口分析的问法

对每个想加的动作，问三个问题：

```
① 这个动作**复用现有的哪个身体**？
   → 找不到 → 需要新身体（最贵，要跟用户要图）

② 需要哪些**可换部件**？现有库里有没有？
   → 缺哪个 → 只要那一个部件（便宜，一句话的事）

③ 需要额外**变换**吗？（位移/缩放/循环）
   → 这个我自己就能做，不用麻烦用户
```

## 六、向用户要素材的话术模板

> ⭐ **核心原则：要「部件」，不要「整张图」；要「原文件」，不要「录屏」。**

### 6.1 缺一个手臂动作

```
我想加「XXX」这个动作，需要一段手臂的动作。

最省事的方式（三选一）：
  ① 一个 GIF（≥400×400、带透明底）—— 像上次揉脸那个就很好
  ② 「没有手臂的底图」+「单独的手臂图」两张 PNG
  ③ 有现成的完整动作图也行

⚠️ 如果是录屏，请先把窗口放大到她至少占 400px 宽 ——
   上次的录屏里她只有 74×79，放大 5.5 倍就糊了。
```

### 6.2 缺一个新姿势 / 新身体

```
想要一个「XXX」的姿势（比如躺着、趴着、背对）。

给我：
  · PNG，≥512×512，透明底
  · 如果只有草图也行，我按现有画风补细节
  · 顺便说一句**她朝哪边**（正面/侧面/背面）
```

### 6.3 缺一个道具

```
想要一个「XXX」道具（比如手机、咖啡杯）。

给我：
  · 一张**草图**（线稿就行）—— 像上次那张笔记本草图，
    我一眼就看懂"要从后面看"
  · 或者直接给做好的 PNG
  · 说一句它**摆在哪**（身前 / 手边 / 头顶）
```

### 6.4 不确定要什么的时候

```
想要「XXX 的感觉」，但我不知道具体长什么样。

给我：
  · 一张**参考图**（别的宠物/动画/照片都行）
  · 一句话说清**你要的是哪种感觉**
  → 我先做一版给你看，再迭代
```

## 七、完整示例：工作中的应用

### 7.1 需求
「工作状态要能看出她在打字」✅

### 7.2 缺口分析

```
① 身体 → 复用 019（手蜷在身前的那个姿势）
② 手臂 → 019 自带的手臂就是"在动"的样子
③ 道具 → 缺一台笔记本
④ 变换 → 手臂上下摆动
```

### 7.3 迭代过程（真实的，走了 7 轮）

| 轮次 | 用户反馈 | 我做的 |
|---|---|---|
| 1 | "看不出在干活" | 程序化画了一台笔记本（屏幕朝我们）|
| 2 | "视角反了" | 给草图 → 改成**背面朝我们** |
| 3 | "要平行四边形" | 梯形 → 平行四边形 |
| 4 | "加个苹果 logo" | 换成苹果（画了 3 次才像）|
| 5 | "用 019 的手臂，上下摆动" | 抠手臂 + 补原位 |
| 6 | "电脑在身体左侧" | 量尺寸后缩小 + 左移 |
| 7 | "**直接用我给的图**" | 用户给「无手臂底图」+「单独手臂图」→ **零瑕疵** |

### 7.4 教训

**第 7 轮才是正解** ✅ —— 前面 6 轮都在"我猜 + 程序化拼" ✅
一旦用户给了**干净的部件图**，问题立刻消失 ✅

**所以方法论的最后一条是**：

> **卡住超过两轮，就停下来向用户要「部件」** ——
> 不要在"猜"上耗时间 ✅

## 八、一页速查

```
输入一张图
   │
   ├─ 有「去掉部件的版本」吗？ ──有──▶ 做差（最准）⭐⭐⭐
   │                              └─▶ 直接裁
   │
   ├─ 对方能给单独部件吗？ ──────有──▶ 直接要 ⭐⭐⭐
   │
   ├─ 是一组帧（GIF/视频）吗？ ──是──▶ 并集裁框 + 保留原位 ⭐⭐
   │
   ├─ 部件是彩色的吗？ ──────────是──▶ 颜色阈值 ⭐⭐
   │
   ├─ 部件是深色的吗？ ──────────是──▶ 相对位置约束 ⭐
   │
   └─ 都不行 ────────────────────────▶ 重建分界线（最后手段）⭐
                                          ↑ 卡两轮就回头向用户要部件

提取到部件
   │
   ├─ 定视角（看 Logo / 灭点 / 近远边）
   ├─ 归一化（内容高 = 435，几何量写成比例）
   ├─ 做成逻辑帧（petdex-map.json）
   ├─ 编片段（clips：帧序 / 时长 / 位移 / 循环）
   └─ 装配 + 校验 + 重打包演示页
```
