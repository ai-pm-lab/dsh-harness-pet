# 桌宠动作帧 · 生成规格书

> 这份文档是给**生图工作区**用的：照着它预先生成动作帧图，
> 生成完直接丢进 `assets/<形象>/` 就能接进桌宠。
>
> 内容不是拍脑袋定的 —— 是**从已经跑通的两个形象反推出来的**：
> `yuexin-miao`（57 帧 / 6 段动画）和 `whale-girl`（27 帧 / 4 段动画）。
>
> ⚠️ **这份规格书是「角色无关」的。**
> 它只说「**要什么动作、什么情绪**」，**不说「五官具体怎么画」** ——
> 因为那是**每个角色自己的事**，由参考图决定。

---

## 一、通用规格（**每一张都要满足**）

| 项 | 要求 | 为什么 |
|---|---|---|
| **画布** | 512×512，PNG | 引擎固定按 512 加载 |
| **内容高** | ≈ **435px**（占画布 85%）| 引擎按"内容高 435"归一化；给大了会被缩、给小了会糊 |
| **底部对齐** | 角色的**站立基线**落在同一高度 | 不然动画里她会**上下跳** |
| **水平居中** | 按**内容包围盒**居中，不是按画布 | 同理，不然会左右漂 |
| **视角** | **正面**、三头身 Q 版 | 侧脸/背影做不了表情 |
| **背景** | 生成时用**纯绿 `#00FF00`**；交付可用透明底 | 绿幕抠图零残留（实测比白底好抠） |
| **一帧一张图** | ❌ 不要精灵图拼格、不要分镜 | 引擎是逐张加载的 |
| **不要文字/水印/边框** | | |

> ⚠️ **内容高 435 这条最重要**。内容只有 150px 的话放大 3 倍就糊了；
> 超过 435 会被缩回去、细节白画。

---

## 一·五、最重要的一条原则（**先读这条**）

> ### 只描述「这一张要变什么」，长相全部交给参考图。

这是从两个形象身上总结出来的**唯一一条铁律**：

| 写法 | 结果 |
|---|---|
| 提示词堆满约束（脸型、五官、配色、比例…699 字）| ❌ 4 张里只有 1 张对 |
| **极简提示词 + 参考图** | ✅ 4 张全对 |

**为什么**：参考图已经把「她长什么样」说清楚了 ✅
文字再说一遍只会**和参考图打架** ✅

**所以下面所有动作描述都写成**：

```
✅ 「开心的表情」      ❌ 「眼睛笑成两条向上弯的弧线」
✅ 「惊讶的表情」      ❌ 「嘴巴张成一个小小的圆形」
✅ 「难过的表情」      ❌ 「眉毛向中间皱、嘴角向下」
✅ 「闭眼」            ❌ 「虹膜消失，只留两条向下弯的线」
```

❌ 那一列**不是错的** —— 它们是**某个具体角色的画法** ✅
如果你要画的角色**恰好**是那种极简贴纸风 ✅ 可以参考 ✅
**但不要把它们当成通用要求** ✅

## 四、⚠️ 生成时**必须注意**的坑（都是真踩过的）

### 1. `working` 这一组**最容易翻车**
- ❌ **每帧独立生成** → 电脑的颜色和大小全不一样（实测帧间 **51~57%** 像素不同），
  连起来像"换了三个场景"
- ✅ **正解**：只生成 `working_0` 一张基准帧，**其余帧从它派生**（只改手 / 只改眼）
- ⚠️ 如果工作区只能逐张出图，**请在提示词里反复强调**：
  「和上一张**同一台电脑、同一个位置、同一个大小**，只改 XX」
- 💡 **电脑越简单越好** —— 有透视、有反光、有 logo 的机身最容易在帧间"长歪"。
  能用一个**纯色方块机身 + 一块屏幕**表达，就别画复杂的（那个苹果标志就返工过好几轮）
- 💡 **电脑建议"背面朝向镜头"** —— 屏幕内容不用画，省事且稳定；
  要画屏幕的话，每帧的内容也得保持一致

### 2. 服装和配饰的**细节要说死**
模型会**默认简化**。凡是"这个角色特有、而且容易画错"的地方，
都要在提示词里点名。**踩过的例子**（供参考，**不是通用要求**）：
- 那个角色是**长袖**，模型默认画成短袖、露出光裸的小臂
  → 要写「**长袖，从肩膀盖到手腕，不是短袖，不要露出小臂**」
- 某个配饰的**层数**要说死（说"细"没用）
  → 要写「**只允许两层：外圈 XX + 一条极细的 YY，YY 下面立刻是 ZZ**」
  → （当时那处是"发箍有两层白，模型多画了第三层"，来回改了 3 轮）

> 💡 **判断标准**：先说清「**哪里不对 + 对的样子是什么**」✅
> 不要说"不好看" —— 模型听不懂"不好看"，听得懂"下方不要有白布" ✅

### 3. **能让模型一次画对的，就不要后期贴**
如果某个部件**压在**另一个部件上面（比如**刘海压在眼睛上**），
任何"区域替换"都会连压着的那部分一起动 ✅
→ **优先想办法让模型一次画对**，而不是事后抠图贴。

### 4. 不要用「参考强度」代替图生图
实测 `reference_strength: 0.92` **不是图生图** ——
拿一张图当底改一处，结果构图整个变了（差异 89%）。
要做"只有一处变"的帧，**只能靠后期合成**，不能指望参数。

### 5. 交付格式优先级
1. ⭐⭐⭐ **PNG 序列 / 透明底** —— 无损，不用抠
2. ⭐⭐ **GIF**（≥400px、带透明）—— 自带每帧时长，适合连续动作
3. ⭐⭐ 动态 WebP
4. ⭐ MP4/MOV —— 要抽帧，**必须先把来源放大**，否则糊
5. ❌ 静态截图 —— 做不了动作

## 五、命名与映射（**不用纠结起名**）

引擎吃的是「**逻辑名 → 文件名**」的映射表（写在 `src/renderer/pet.js` 的
`FRAME_FILES` 和 `assets/<形象>/manifest.json` 里）。
所以你交上来的文件**叫什么名字都行**，我加一张映射表即可。

唯一的要求：
- ✅ **一个动作一个文件**
- ✅ 文件名用**英文或拼音**，别用空格
- ❌ 不要拼成精灵图 / 分镜格

如果你愿意一次到位，用这套命名最省事（我不会再改）：
```
awake  blink  drowsy  sleep  startle  eat  stretch
patHappy  angry  angryBlock
wave_1  wave_2  wave_3
work_0  work_1  work_2
need_input  blocked
ready_0  ready_1  ready_2  ready_3  ready_4
```

## 六·五、给某个具体角色用的时候，再补一张「角色补充表」

这份规格书是角色无关的 ✅ 真开工前，**每个角色补一张小表**就够了：

```markdown
## <角色名> 补充

### 她的「开心」怎么画？
（一句话，或者直接指参考图）

### 她的「难过」「生气」「受惊」怎么画？

### 她身上最容易画错的地方是哪几处？对的样子是什么？
（这一栏最值钱 —— 每一条都能省好几轮返工）

### 参考图放哪几张？
（建议 5~10 张：正面全身 + 关键部件特写）
```

> 实测：**这一栏写得好不好，直接决定返工几轮** ✅
> 上一个形象光是"某个配饰到底是几层"就来回改了 **3 轮** ✅

## 七、怎么验证生成出来的能用

丢给我之后我会跑：

```bash
node tools/verify-pet.mjs <形象名>      # 张数、命名、和清单是否一一对应
python3 tools/verify_assets.py          # 逐张解码：尺寸、透明通道、轮廓比例
```

**自己也能先看一眼的**：
- 每一张的**内容高度**是不是都在 400~440px 之间
- 同一组动画的**站立基线**是不是在同一高度
- 抠图后**有没有残留的绿边**
